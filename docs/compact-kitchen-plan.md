# 調理画面の最小表示・横画面固定レイアウト計画

作成日：2026年10月15日  
状態：実装・ローカル確認・GitHub Pages公開更新完了。対象は現行のGitHub Pages運用と共有調理画面。

## 目的と設計方針

操作画面の常駐説明を徹底してなくし、操作方法は画面内マニュアルからのみ確認する。画面に残すのは操作ボタン、識別子、必要な数値、提供状態など実際の操作に使う情報に限定する。補足説明、手順、成功通知、装飾的な見出し・件数・フッターは表示しない。説明を削除する際はマニュアルへ集約し、ボタンの `aria-label` とキーボード操作を維持する。保存失敗など操作できない原因や破壊操作の確認は、その場で必要な最小限の表示にする。

横画面では上部を「左：戻る、その下に生地」「中央：小型のm/n呼び出し」「右：右端まで完成ボックス」とし、残りの下部を横並びの鉄板2枚に充てる。通常の調理画面は縦横ともスクロールさせない。マニュアル・データ管理など利用者が開くダイアログは、閉じる操作を確保して内部をスクロールできる。

- 戻るは既存の直前操作取り消し（Undo）で、画面左上に固定する。
- 生地は残数 `n/6` と残り `mm:ss` を1列で表示する。nは配置済み数ではなく未使用の個数。未開始・使い切り・期限切れの開始/再開操作は小型ボタンまたはタイマー領域の操作として維持し、期限切れで新規配置できない既存仕様を変えない。
- 呼び出しは上下2組の左右矢印でm/nを選び、中央タップで照会する。矢印だけでは照会内容を変更しない。現在の大型楕円・周囲の説明を縮小/除去する。
- 完成ボックスは呼び出したID、提供状況、提供可能時の残り時間、提供ボタンを表示する。提供済み・期限切れ・未準備には提供ボタンを出さない。
- 鉄板の横幅と2行3列の配置を維持し、縦幅を短縮する。座標の変換・長押し移動・温度操作を壊さない。

## 確認済みの実装と制約

- `app/kitchen.tsx` がPages/PC共通の画面、照会、操作送信、マニュアルを実装し、`app/globals.css` に横画面指定と生地・完成ボックスのスタイルが重複している。生地カードやヘッダー等の説明と余白が現在の縦幅を占めている。
- 現行照会 `findDeliverySearchMatches` は再採番される `id` と安定した `archiveId` / `ExecutionRecord.id` を両方検索するため、異なる個体が同じ検索に一致し、「画面ID」「記録ID」が並ぶ。
- 削除機能廃止後も `lib/kitchen-model.ts` の `relabelEntities` は提供後などに内部 `id` を詰め直す。既存の記録・CSVを変更せず、鉄板・呼び出し・完成ボックスで利用者に見せる唯一のIDを安定した `archiveId`（記録では `record.id`）に統一する。内部コマンドには既存の `id` を保持し、`entityKey` で同じ個体へ解決してから送信する。モデル・保存schemaの変更は行わない。
- 旧データやID衝突回避でUUID形式の `archiveId` が存在し得る。旧UUIDは保存・記録・CSVに保持する。今回の数値呼び出し範囲は従来の `1-1`〜`8-24` を維持し、UUID入力や履歴再採番は追加しない。このため旧UUIDの完成品は数値呼び出しの対象外となる。
- 現在の中央タップは照会だけで、保存状態や `isRecalled` を変更しない。この方式を維持する。
- `completionStatus` / `completionTimer` は元の絶対期限を用いる。提供可能時は期限との差を切り上げ秒で `mm:ss` 表示し、呼び出しで30分を再開始しない。`now >= serveDeadlineAt` で提供不可となる。
- 完成品の既存 `remove` コマンドは期限前なら `servedAt` を記録して完成品を取り除く。提供ボタンはその経路を使い、最新の `entityKey` 対象から内部 `id`・versionを取り直して既存generation/pending制約で送信する。確定後も同じ照会に「提供済み」を表示する。操作中に期限が到達した場合は既存のモデル判定を優先する。

## 検証と受け入れ条件

テストファイルを追加しない。テストスイートは実行せず、`npm run typecheck`、`npm run lint`、`npm run build:pages`、共有画面の互換性確認として `npm run build:pc`、`git diff --check` とブラウザーでの操作・寸法確認を行う。実施した検証のみ結果として報告する。

1. 横画面（例：844×390、915×412）で、Undo・生地残数/時間・m/n呼び出し・完成ボックス・鉄板2枚を一画面で確認できる。通常画面のdocumentに縦横のスクロール余地がなく、下段・楕円・温度矢印も欠けない。縦画面でも必須操作へ到達できる。
2. 生地の初期/稼働/使い切り/期限切れで残数の意味と再開操作が正しく、稼働時は `6/6` から配置ごとに減る。常駐の説明、期限時刻、配置済み数、ID区間説明はなく、必要な操作情報はマニュアルで読める。
3. 他個体の提供等で内部 `id` が変わっても鉄板・呼び出し・完成ボックスの利用者向けIDが変わらず、異なるIDの対象が混在しない。CSVのIDや既存記録は変更されない。
4. 期限前の完成品を呼び出すとID・提供可能・元の期限からの残時間・提供ボタンが出る。矢印のみで結果を変えず、再呼び出しで期限を延長しない。未準備/該当なし/提供済み/期限切れには対応する状態だけを表示する。
5. 提供ボタンで対象1個だけが提供済みになり、連打/処理中操作を防ぐ。確定後の再照会・再読込でも提供済みが保持される。期限境界では既存モデルの提供不可判定に従う。
6. 通常操作時に案内帯・説明文・大きな成功通知が鉄板を覆わない。マニュアル、データ管理、復元/リセット確認は必要なときに開け、横画面でも閉じられる。新規配置・移動・加熱・回収・Undoの基本経路をブラウザーで確認する。
7. 対象外の差分がないことを確認してコミット/pushし、既存のGitHub Pages公開処理の完了後、公開ページを更新して新レイアウトを確認する。運用中の調理データを公開確認のために変更しない。

## リスク・未決事項と自己確認

- 極端に狭い横画面では操作領域が小さくなる。固定高の切り取りだけで達成せず、余白と鉄板の実表示高を調整し、ブラウザーで最小領域と欠けを確認する。横幅を確保したままSVGを縮める場合はポインター座標と描画の対応を確認する。
- 通常画面のスクロール禁止をダイアログへ波及させない。モバイルブラウザーのツールバーとsafe-areaを考慮して利用可能高を決める。
- 旧UUIDが数値呼び出し対象外である制約は上記のとおり。履歴の書き換えや新しいID移行は今回行わない。
- 主担当の判断により、安定ID表示と内部コマンドIDを分け、既存データを保全する。照会/提供は既存モデルで実現可能であり、依存実装を止める未決要件はない。所有権、表示原則、期限境界、公開完了までの受け入れ条件を自己確認済み。
