# スマートフォン向け鉄板切替 UI 実装計画（撤回）

作成日：2026年10月9日　｜　状態：2026年10月10日に撤回。旧仕様へ復帰。

この計画で追加した鉄板切替 UI は撤去した。現在はスマートフォン縦画面で2枚を縦並び、横画面で2枚を横並びにして同じ画面に表示する。以下は切替 UI を実装した時点の記録。

## 当初の目的・期待する挙動

スマートフォンでは鉄板1枚を画面幅いっぱいに大きく表示し、左右ボタンで鉄板1・2を切り替える。初期表示は鉄板1。デスクトップは現在どおり2枚を同時に表示する。切替は表示だけに作用し、盤面データや調理操作を変えない。

## 調査結果・制約

- `cooking-app/app/kitchen.tsx` の `KitchenView` がPC版とPages版で共用され、`.plates` 内に鉄板1・2を常時描画している。盤面は16:9のSVGで、イベント処理は各盤面の鉄板番号を維持する。
- `cooking-app/app/globals.css` はデスクトップで横並び、スマートフォン縦向きで縦並びにする。縦向きの盤面幅は2枚を縦に収める寸法に制限されている。複数の重複メディアクエリがあるため、新規ルールは既存の最終指定との優先順位を確認する。
- 統合レビューで、低いウィンドウ高のデスクトップもモバイル切替対象になることが判明した。スマートフォン横向き判定は、幅900px以下・高さ600px以下に加えて coarse pointer を条件にする。狭い縦向きの幅600px以下判定は維持する。
- 待機中の下段アイテムは、真上が実際に使用中なら計測を開始し、空いていれば移動を試みる。移動先をブロックする過密判定は実際の占有判定と別に扱う。過密で移動できない場合は待機状態を維持して理由を表示する。
- `useState` と左右矢印アイコンは既に利用中。選択中の鉄板は一時的な画面状態とし、保存や同期の変更は不要。
- リポジトリ内に追加の `AGENTS.md` はない。

## 影響範囲・担当

**GPT-6 Luna 実装worker** が次のファイルを一括担当する。

- `cooking-app/app/kitchen.tsx`：選択状態、狭い画面用の左右ボタン、現在の鉄板番号表示、カードへの選択状態付与、待機中タップの実占有判定。
- `cooking-app/lib/kitchen-model.ts`：過密状態とは独立して対象セルのアイテム占有を判定するヘルパー。
- `cooking-app/app/globals.css`：狭い画面で非選択盤面を隠し、選択盤面を利用可能幅まで拡大する。デスクトップ表示を維持する。
- `cooking-app/README.md`：スマートフォンの鉄板表示の説明を現在の切替動作に合わせる。

Solが最終差分を確認する。独立レビューは差分の規模に応じて判断する。

## 実装手順

1. 選択状態を鉄板1で初期化する。左ボタンは前の鉄板、右ボタンは次の鉄板へ切り替える。鉄板1では左、鉄板2では右の境界ボタンを無効化し、表示位置は中央の番号で示す。ボタンには移動方向が分かるアクセシブル名を付ける。
2. スマートフォン向けに、縦向き幅600px以下と、coarse pointer の幅900px以下・高さ600px以下では選択中のカードだけを表示する。16:9比率を保って利用可能な横幅を使う。デスクトップでは2枚を表示し、切替UIは隠す。
3. 切替後も対象鉄板の件数、配置、タイマー、温度調整が既存どおり動くことを差分と画面表示で確認する。

## 受け入れ条件・検証

- スマートフォンの縦向き・横向きで盤面が1枚だけ大きく表示され、左右ボタンで鉄板1・2を切り替えられる。
- 選択中の鉄板に対するタップ・キーボード操作だけが有効で、データや操作対象が混同されない。
- 低い高さのfine pointerデスクトップは2枚表示を維持する。過密した鉄板で待機中アイテムをタップした場合、真上のマスが空いていれば過密理由を表示して待機状態を保ち、実際に占有中の場合のみ計測を開始する。
- READMEのスマートフォン向け説明が1枚ずつの切替操作と一致する。
- デスクトップは両方の盤面を現状の横並びで表示する。
- 差分レビューと `git diff --check` を行う。必要に応じて型確認・PC/Pagesビルドを行う。テストの追加・実行はユーザーから依頼がないため行わない。

## リスク・未確定事項

- スマートフォン横向きも対象にするため、縦向きは幅600px以下、横向きは幅900px以下かつ高さ600px以下のcoarse pointerに絞る。小型タブレットが該当する可能性は残る。fine pointerのデスクトップは2枚表示を維持する。
- 過密盤面では見た目上のセル位置と通常の割当可能セル数が一致しないことがある。待機アイテムのタップ判断では表示位置の実占有を先に確認し、移動可否は既存の過密ルールに任せる。
- 盤面拡大により、縦向きではページ全体が画面高に収まらないことがある。既存のスクロールで全操作へ到達できるようにする。
- 非表示カードをDOMに残す場合、切替時に非表示盤面のポインター捕捉やキーボードフォーカスが残らないよう確認する。

## 実施結果

- スマートフォン向けに鉄板選択ボタンと選択中表示を追加し、非選択の盤面を非表示にした。初期表示は鉄板1で、左・右ボタンは前後移動として動作する。デスクトップは従来どおり両方を表示する。
- 型チェック、Pages版・PC版の本番ビルド、`git diff --check` が成功した。自動テストは実行していない。
- 独立レビューでは具体的な問題は報告されなかった。

## 統合レビュー後の修正

- 過密状態で空の移動先を使用中と誤認して計測を始める問題を修正する。真上のセルが実占有中かを独立判定し、空きセルへの移動が過密理由で拒否された場合は待機状態を維持する。
- 横向きモバイルの切替条件にcoarse pointerを追加し、低いウィンドウ高のデスクトップでは従来の2枚表示を保つ。
- READMEのスマートフォン説明を切替UIに合わせる。
- 統合後に型確認、PC/Pagesビルド、差分確認を行う。自動テストは実行しない。

## 撤回内容

- 選択中の鉄板を保持する画面状態、左右の切替ボタン、非選択の鉄板を隠すCSSを削除した。
- 旧仕様どおり、スマートフォンでは縦画面で2枚を縦並び、横画面で2枚を横並びに表示する。
