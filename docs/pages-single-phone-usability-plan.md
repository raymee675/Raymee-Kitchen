# GitHub Pages版（固定スマートフォン1台）の使いやすさ改善計画

作成日：2026年10月8日　｜　状態：実装済み（GitHub Pages公開・固定スマートフォン確認は未実施）

## 目的と期待する動作

対象を、**固定した1台のスマートフォンで、同じブラウザーまたはホーム画面アイコンからGitHub Pages版を使う運用**に限定する。PC版の起動、端末登録、複数端末共有は変更しない。

初めて開いた人がヘルプを探さなくても、楕円の状態ごとの操作、温度調整、焼き上がりから提供までの移動を理解できるようにする。保存場所と消失条件を操作画面で伝え、記録CSVと盤面バックアップの違いを明確にする。GitHub Pagesに配信された画面と、同じスマートフォンに残ったService Workerキャッシュのどちらでも、表示中の説明が実際の操作と一致することを目指す。

## コード調査で確認した現状・制約

- Pages版は `cooking-app/pages-client/src/main.tsx` から共通画面の `PagesKitchen` を使う。主要な操作とヘルプは `cooking-app/app/kitchen.tsx`、見た目とタップ領域は `cooking-app/app/globals.css` にある。Pages固有の説明や導線は `__PAGES_MODE__` で分岐できる。
- 現行の状態別操作は、下段の空きマスで配置、白い楕円で90秒計測開始、下段の黒い調理中楕円で同じ列の上段へ移動、赤い楕円で完成ボックスへ移動、完成ボックス項目で提供済みまたは提供不可の記録となる。画面下のガイドは空きマスと調理中楕円の意味を一行にまとめ、白い楕円を押すと計測が始まる説明が主要画面上にない。
- 温度矢印の透明な入力矩形はSVG座標で幅64、表示幅約358pxの鉄板では約14px相当になる。可視の矢印部分も約10px相当で、スマートフォンでは誤タップしやすい。入力は鉄板SVG全体のPointer Eventsで判定するため、対象を広げるときは中央の楕円タップや隣の操作と競合させないこと。
- 完成ボックスは鉄板より上にあり、画面が鉄板2枚分スクロールした後に焼き上がると、提供操作のために上へ戻る必要がある。件数は上部の調理状況に表示されるが、完成ボックスへ移動する直接の案内はない。
- Pages状態は `cooking-app/lib/local-kitchen-storage.ts` のアプリ専用 `localStorage` キーへ保存し、`cooking-app/lib/use-kitchen-local.ts` が読み書き、複数タブの排他、Service Worker更新を扱う。データは別端末や別ブラウザーと共有されず、サイトデータ削除や端末交換からの自動復元もない。
- 共通画面にあるCSVは完了済み実行記録の書き出しで、調理中の盤面・完成ボックス・採番状態を復元するバックアップではない。READMEのPages節はサイトデータ削除時の消失と「記録はCSVで保管」を説明するが、CSVで盤面も復元できると誤解されない案内が必要。
- 前回の公開画面確認では、公開版ヘルプに現行コードにない長押し移動の説明が残っていた。Service Workerは新しい版を自動適用せず、待機版をユーザーの「更新を適用」操作で切り替えるため、公開成果物の更新だけで既存端末の説明が即時に切り替わるとは限らない。現行ヘルプにはPC向け操作・説明も含まれている。
- `docs/single-phone-github-pages-architecture.md` は、JSONバックアップを初期対象外とし、必要時の追加案として記載している。今回JSON復元を実装する場合は、その記述と実装状況を更新する。

## 実装方針

### 1. Pages向け操作説明と公開版の一致

- Pagesのヘルプと画面下ガイドを、状態ごとの短い説明に改める。「白＝90秒開始」「黒い下段＝同じ列の上段へ」「赤＝完成ボックスへ」「完成ボックス＝提供済み／提供不可」を操作画面に近い位置で示す。タップ操作であることを明記し、長押し移動の説明は置かない。
- Pages版のヘルプからPC専用のキーボード・共有の説明を外す。PC版の説明は既存どおり保持する。
- ヘッダーまたは初回利用時に邪魔にならない常設メッセージで「このスマートフォンのこのブラウザーに保存」「別ブラウザー・別端末とは共有しない」「サイトデータ削除や端末交換で消える場合がある」を知らせる。初回案内で操作をブロックしない。ロック中は通知・アラームが保証されないこともヘルプとREADMEに残す。
- 新しいPages版を公開後、Service Worker待機版の適用を含め、公開URLでヘルプと操作を確認する。公開確認前に古い画面が更新済みと扱わない。

### 2. スマートフォンのタップ領域と操作発見性

- Pages版で温度の上下入力領域を拡大し、実機のCSSピクセルで概ね40px以上の押しやすさを目標にする。中央の楕円操作や隣接する温度ボタンとのタップ判定を分離し、楕円内の温度調整が計測開始・移動にならないことを確認する。
- 温度の初期値96℃、調整単位1℃、計測時間固定90秒を温度コントロール付近とヘルプで説明する。温度はユーザーが調整する記録値であり、実測センサー値と誤認させない。
- CSS・条件分岐はPages版に限定できる形にし、共通画面を使うPC版のレイアウトや操作を意図せず変えない。

### 3. 完成ボックスへ戻る導線

- 完成ボックスの見出しへ移動する、スマートフォン向けの見つけやすい「完成ボックスへ」導線を追加し、完成品が1件以上ある間は件数も示す。
- 利用者が今見ている鉄板からすぐ移れるようにし、タイマー終了だけを理由に画面を自動スクロールしない。既存の30分カウントと提供済み／提供不可操作は保つ。

### 4. 端末内データの保全とエクスポート案内

- 既存CSVは「実行記録CSV」として案内し、完了記録の保存用であって現在の盤面復元には使えないことを明記する。
- 盤面・調理中タイマー・完成ボックス・実行記録・次のIDを一つに含む、Pages版専用JSONの手動バックアップ書き出しと読み込みを追加する。保存・読み込みは既存のアプリ専用キーとlocalStorageのスキーマを使い、Pagesのデータだけを対象にする。通信やクラウドへの送信は行わない。
- 読み込み前にバックアップ日時と置き換え対象の件数を示し、明示確認後に現在のPages盤面を置き換える。ファイルの形式・バージョン・各データを検証し、不正または未対応なら現在の盤面を変更しない。復元成功後は画面と保存状態を同時に反映し、保存失敗時に成功扱いしない。
- 既存のlocalStorage盤面が破損して読み込めない場合も、当該画面がWeb Lockを確保し、元データを読み出せる間は検証済みバックアップからの復旧を案内する。復旧可否の事前判定では追加データを書き込まない。確認後の本書き込みが失敗した場合は成功扱いせず、既存データを画面状態で置き換えない。ロック未取得や保存API自体へアクセスできない場合は復元可能状態として扱わない。
- JSONのバックアップ操作は「データ管理」内にまとめ、スマートフォンのヘッダーを複数ボタンで埋めない。CSVの既存機能は維持する。

## 影響ファイル・担当

**GPT-6 Luna実装worker（PagesのUX・保存機能を一貫して担当。共通画面のPC挙動を保護する）**

1. `cooking-app/app/kitchen.tsx`：Pages向け状態別操作説明、完成ボックスへの導線、データ管理UI、JSON読み込み確認と結果表示を実装する。Pages固有UIは `__PAGES_MODE__` で限定する。
2. `cooking-app/app/globals.css`：Pagesで使う温度ボタンのタップ領域、短い操作ガイド、完成ボックス導線、データ管理UIのスマートフォン表示を整える。必要なら `.pages-kitchen` などのスコープを設け、PC側へ意図しない変更を出さない。
3. `cooking-app/lib/local-kitchen-storage.ts`：Pages JSONバックアップ形式の生成・検証・読み込み変換を追加する。現行schemaVersion 6以下を読み込める互換性と、既存localStorageキーを維持する。
4. `cooking-app/lib/use-kitchen-local.ts`：検証済みバックアップを既存の編集ロック内で読み込み、revision/generationを安全に進めて保存・公開する。インポート失敗時に現在盤面を維持する。
5. `cooking-app/README.md`：Pagesの保存範囲、消失条件、CSVとJSONの違い、バックアップ・復元手順を説明する。
6. `docs/single-phone-github-pages-architecture.md`：JSONバックアップの採用に合わせ、従来の「初期対象外」記述と実装状況を更新する。

**Sol coordinator**：実装前にこの計画を維持し、実装後にPages限定、ローカル保存の互換性、Service Workerの公開反映範囲を確認する。

**実装者とは別のGPT-6 Luna reviewer**：JSONインポート時のデータ破壊・不正ファイル、ID/実行記録/完成ボックスの整合性、既存利用者のスキーマ移行、タップ範囲の操作競合を独立レビューする。

## 実装順

1. Pages向け文言とヘルプを整え、現行操作だけを案内する。保存場所・消失条件と画面ロック中の制約を常設または初回案内で知らせる。
2. 温度操作のタップ領域を拡大し、中央の楕円操作との判定を分ける。
3. 完成品がある時の「完成ボックスへ」導線を追加する。
4. バックアップJSON形式と検証境界を確定し、Pages専用の書き出し・確認付き読み込みを追加する。
5. READMEとアーキテクチャ文書を更新し、公開URLの更新操作と古いキャッシュを含めて表示説明が合っていることを確認する。

## 検証・受け入れ条件

- Pages版ヘルプと画面内案内に長押し移動やPC専用操作がなく、白・黒・赤・完成ボックスの各タップ結果が現行コードどおりに説明される。PC版のヘルプ・挙動は変わらない。
- スマートフォン相当の表示幅で温度ボタンを押しやすく、温度変更が楕円タップ操作を誤発火させない。下段から上段への移動、タイマー開始、焼き上がり後の回収は従来どおり成立する。
- 完成品がある時に鉄板から完成ボックスへ短い操作で移動でき、提供済み／提供不可の確定を終えられる。自動スクロールはしない。
- 利用者がデータの保存端末・ブラウザーと消失条件、ロック中に確実な通知がないことを画面またはヘルプで確認できる。
- JSONの書き出し・読み込みを往復して、鉄板上の待機・調理中タイマー、完成ボックス、実行記録、ID採番が保持される。CSVは実行記録だけであると明確に区別される。
- インポートのキャンセル・不正ファイル・未対応バージョン・localStorage書込エラーは現在盤面を成功扱いで置き換えない。旧schemaVersion 1〜6の利用者データは従来どおり開く。
- localStorageの保存データが破損して通常盤面を読み込めない場合でも、排他ロックを保持し、検証と利用者確認を通ったJSONバックアップから復旧できる。復旧前に追加容量を消費する試し書きはしない。本書き込みが失敗した場合は成功扱いしない。
- PagesのService Worker更新前後に公開ヘルプと実操作が一致する。新しいビルドを用意しただけで公開済みと報告せず、公開URLを確認した場合のみ公開版の反映を報告する。
- 実施済み：手動の差分レビュー、独立コードレビュー、`git diff --check`。自動テスト・型確認・Pagesビルドはこの依頼では実行していない。固定スマートフォンでの指押し・ホーム画面起動・オフライン復帰とGitHub Pages公開反映は未確認。

## リスク・未確定事項

- 固定スマートフォンの機種・OS・ブラウザーはこの計画では特定されていない。40px以上を目標とするタップ領域は、実機の表示幅と誤操作を見て調整する。
- JSON復元は現在データの置き換え操作になる。確認、バックアップ日時と件数の表示、形式検証、書込成功後の反映が欠けると、誤ファイルによるデータ消失につながる。
- localStorage容量が不足していても、復元ファイルが現在の保存値より小さければ置き換え可能な場合がある。復旧前に一時キーを書き込むと追加容量が必要になるため、排他ロックと元データの読み出しだけを事前確認し、確定後の本書き込み結果を扱う。
- 手動バックアップは、利用者が継続して端末外へ保存しない限りデータ削除・端末故障を救済できない。クラウド同期や自動送信を追加しない。
- Service Worker待機中の古い画面はユーザーが更新を適用するまで残り得る。公開版と端末内版の両方で操作説明を確認する必要がある。
- 画面ロック中に確実なJavaScript実行・通知・音はPages版だけでは保証できない。Wake Lockは補助表示にとどめ、ロック中のアラーム機能を追加したと案内しない。
