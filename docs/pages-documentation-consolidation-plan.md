# Pages版ドキュメント統合 実装計画

作成日：2026年10月10日

状態：完了（2026年10月10日）。

## 目的と期待する状態

GitHub Pages版を唯一の現行運用・サポート対象として文書を整える。固定スマートフォン1台の同じブラウザーで使う方式、端末内保存、Pagesへの静的配信、Actionsによるビルド・公開を現行仕様として一か所にまとめ、READMEを利用者と開発者の入口にする。旧Site案、複数端末共有案、PCサーバー案は履歴資料として残し、現行手順と取り違えないようにする。

文書上は、PC版ソースコードを削除済みとは記さない。現在のworktreeにはPC用サーバー、Vite設定、PCクライアント等が残っている。これらはリポジトリ内のlegacy実装で、現在の運用・サポート対象ではないことを明記する。Pages向けビルドとActionsの公開成果物は静的Pages版を対象とし、PCサーバー、SQLite、管理画面、WebMCPを配信対象に含めないという現行方針を保つ。

## 調査結果と制約

- docs/single-phone-github-pages-architecture.md は、固定スマートフォン1台、登録・認証・端末間共有なし、localStorage、Service Worker、画面維持、Web Locks、Pages専用ビルドという現行方針を既に詳しく記録している。これを新しい正本に拡充する。
- cooking-app/README.md はPC版をタイトルと起動手順の中心に置き、Windowsサーバー、端末登録、SQLite、PCスリープ等を現行利用方法として説明する一方、後半にPages版の説明を併記している。Pages専用の短いクイックスタートへ改める必要がある。
- docs/implementation-plan.md、docs/hosting-options.md、docs/cloud-architecture.md、docs/pc-mobile-implementation-plan.md の冒頭は、PC版のみが現行でPagesやSiteは対象外という旧判断を示している。本文は当時の経緯を残す価値があるため、移動・削除せず、アーカイブ表示と現行正本へのリンクを直す。
- docs/dough-timer-plan.md は未実装機能の現行計画だが、PCとPages双方の対応、SQLite、PC API、restore、WebMCP、PC同時操作を実装対象にしている。今回の方針に合わせ、Pages運用に必要な仕様と受け入れ条件を残し、PC専用の実装・サポート要件を現行対象から外す。
- docs/github-pages-deployment-plan.md は2026-10-03時点の記録として、Actions成功と公開URLのHTTP 200、同時点のWeb Locks実行時エラーを記録している。その後、commit `67de70e`で修正がmainに反映され、2026-10-09の公開記録ではActions run 13の成功とHTML・JavaScript・CSSのHTTP 200が確認されている。正本はこれらを時系列でまとめ、「公開資産の応答」と「固定スマートフォンで運用確認済み」を区別する。
- mainにはJSONバックアップ／復元、スマートフォン操作の変更、撤回された鉄板切替案を記録するMarkdown資料が追加されている。資料索引へ含め、個別資料の当時の仕様が現行方針を上書きしないことを明示する。
- docs/verification.md はSite版の履歴記録であり、現在のPages版検証結果として扱わない。docs/github-pages-replacement-assessment.md と docs/connection-delivery-architecture.md には既に旧前提・不採用の表示があるため、本文は変更せず索引で分類する。
- docsには機能別の計画・実装記録が多数ある。個々の技術的記録は保持し、現行の運用方式を規定する文書とは役割を分ける。索引が各記録の機能仕様や実装状況を書き換えるものではない。
- この計画の作業範囲は文書のみ。アプリコード、設定、Pages公開状態、データは変更しない。テストは追加・実行しない。

## 正本と文書の役割

1. docs/single-phone-github-pages-architecture.md を、現行運用・サポート範囲とアーキテクチャの正本にする。冒頭に適用範囲、PCコードの残存状況、Pages成果物の境界、文書の更新時点を記す。固定スマートフォン1台、1ブラウザー、認証・共有なし、端末内保存、オフライン条件、公開範囲、データ消失条件、運用上の制約、デプロイと実機確認の状況を一貫してまとめる。
2. 新設する docs/README.md を資料の入口とし、正本、利用者向けREADME、現在の機能計画、デプロイ履歴、完了済み・過去の機能記録、旧構成アーカイブを分類してリンクする。新しいPages usability、待機楕円移動、撤回済み鉄板切替計画も役割を添えて索引し、どの資料が運用方針を決め、どの資料が個別機能の設計・履歴だけを記録するかを説明する。
3. cooking-app/README.md は利用者向けPagesクイックスタートと最小限の開発者向けPages手順にする。既知の公開URLは、デプロイ記録上のURLであることと確認日を添えて示す。現在の稼働を確認していない場合は、未確認の状態を明記する。PC起動、管理画面、端末登録、SQLite運用を現在の利用手順として載せない。
4. docs/dough-timer-plan.md はPages向け機能計画として範囲を限定する。生地タイマーのデータ契約、ローカル保存、共通UI、Pagesでの直列化・競合処理、保存移行と受け入れ条件を保つ。PC runtime、SQLite保存・復元、WebMCP、複数PCの同時操作を現行実装要件から外し、共通コード変更によって既存PCコードの型整合が必要になる場合も、PC機能の動作保証やサポート拡張とは区別する。
5. 過去案・過去記録はファイル移動や削除をせず、先頭に「現行手順ではない」「現行正本へのリンク」を置く。本文の当時の決定や検証記録は残す。相対リンクの破壊を避け、履歴の内容を現行仕様へ上書きしない。

- docs/single-phone-github-pages-architecture.md が運用アーキテクチャの正本で、docs/README.md が文書群の入口になっている。cooking-app/README.md から正本と索引へ辿れる。

## リスクと未決事項

- 「Pages版を使う」ことと「PC版のソースをリポジトリから物理削除する」ことは別の状態である。今回の文書作業ではPCコードを削除せず、残存・非サポートを明示する。コード削除が必要なら別途、成果物と既存運用への影響を確認する。
- 公開URLと資産のHTTP 200は2026-10-10の観測であり、以後の到達性を保証しない。スマートフォン実機の「利用確認済み」と混同しない。
- 各機能計画は作成時点のコードや検証内容を記録している。今回すべてを書き換えると履歴が失われ、対象が広がる。索引と明確な冒頭表示で現行運用文書との役割を分け、個別機能の現行要件に影響する矛盾だけを対象にする。
- READMEの公開URLを実用手順として掲載できるのは、そのURLが現在も正式な利用先として採用されている場合に限る。現状確認が得られない場合はURLを「最終デプロイ記録に記載されたURL」と注記し、稼働保証をしない。
