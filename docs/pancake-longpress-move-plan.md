# お好み焼き削除の廃止と長押し移動の実装計画

作成日・改訂日：2026年10月14日　｜　状態：実装・ローカル検証完了、公開更新準備中。両鉄板間の空きマス移動を実装。完了後のpush・公開更新も依頼済み。

調査対象は `ver-beta` の `59015df`。計画作成開始時の作業ツリーはcleanだった。現行運用は[固定1台のスマートフォンで使うGitHub Pages構成](single-phone-github-pages-architecture.md)に従う。

## 目的と期待する動作

現在の「楕円を長押しして鉄板外へドラッグすると削除する」操作を廃止し、楕円の長押しを鉄板上の移動操作へ変更する。新しい削除コマンドも受理しない。既存の調理・提供状況照会・保存・記録を維持する。

ユーザー回答「別の鉄板も含め、空きマスへ移動できる」に従い、長押し移動の範囲を以下のように確定する。

- 楕円本体を450ms長押ししてからドラッグし、**同じ鉄板または別の鉄板の空きマス**で離すとセル中央へ移す。両鉄板の各6マスが対象で、上段・下段・左右・鉄板間の移動を許可する。列や隣接セルだけという制限は設けない。
- 使用中のマス、両方の鉄板の外や鉄板間の隙間で離した場合はキャンセルする。位置交換・他の楕円の押し出し・削除は行わない。元の鉄板の元マスで離す場合も無変更とする。
- 待機中の白、計測中の黒、焼き上がりの赤を移動対象とする。長押し移動では計測を開始せず、赤い楕円も回収しない。
- 短いタップは現行どおり。下段の白は真上が空いていれば上段へ移動、真上が使用中なら計測開始。上段の白は計測開始。下段の黒は真上の空き上段へ移動、上段の黒は移動しない。赤の短いタップは回収して内部30分計測を開始する。
- 温度矢印は長押し移動の起点にしない。短いタップでの温度調整と、下段の空きマスへの新規配置は維持する。

初回依頼では計画作成までを行った。その後、ユーザーから本計画に沿う実装と、完了後のpush・公開更新を依頼されたため、現在は実装を進める。

## 現行コードから確認したこと

- `cooking-app/app/kitchen.tsx` の `down` / `scheduleLongPress` / `armLongPress` / `move` / `up` がPagesの削除操作を持つ。450msを待ち、12 CSS px以上動かして両方の鉄板外で離すと `delete` を送る。pointer capture、cancel / lost capture、generation・内部key・画面ID・versionの確認がある。
- `outsideBothPlates` は盤外削除の判定用で、`deleteDragCue` とCSSの `delete-dragging` が削除予告を表示する。現状は長押しで鉄板内へ移動できない。
- `kitchen-model.ts` の新規 `delete` はPagesだけで有効。楕円を除き、generationを増やす。開始済みなら盤外破棄の実行記録を作り、元の楕円を `UndoEntry.delete` に保存する。未開始の場合は実行記録を作らない。
- 通常の `move` と `gridMoveBlockReason` は「同一鉄板・下段から同じ列の上段」だけを許可する。短いタップと既存WebMCP/APIがこの経路を使う。移動先の占有・過密はモデルでも検証する。
- 鉄板は3列×2行。`gridCellAt` / `nearestGridCell` と `gridDropBlockReason` がセル選択・占有・過密検査を持つ。旧過密データは座標を保持し、両鉄板が6枚以下になったときに正規セルへ整理する。
- `UndoEntry` は配置・移動・旧削除を最大50件保持する。配置Undoは新規配置を取り消して採番・生地残数を安全に戻す。移動Undoは元座標へ戻す。旧削除Undoは元の楕円を復元して対応する破棄記録を除く。
- `movedToUpperAt` は現在の上向き `move` 成功時刻で、CSVの「下段→上段移動時刻」に使う。移動Undoでは一律nullに戻るため、往復・複数移動を許可する場合は直前の時刻を復元する情報が必要。
- `keyboard` の `Delete` キーは `delete` ではなく赤い楕円の回収 `remove` に割り当てられている。削除廃止時にはこの割り当てを外し、Enter / Spaceによる既存の操作は維持する。
- Pages保存schemaは12。JSONバックアップとPC保存・復元も共有正規化を経由する。過去の `UndoEntry.delete` と「盤外破棄」の実行記録が保存済みデータに存在しうる。
- 現行の完成ボックスUIはm・n選択による提供状況の照会だけを表示する。今回、文字入力検索やタイマーカードを復活させない。

## 実装方針と保存互換

### 新規削除を止め、過去データを保つ

UIの `delete` 送信、盤外削除判定、削除予告・削除説明を取り除く。`Command` / `parseCommand` / `applySnapshotCommand` の新規削除受付を廃止し、旧クライアントや直接操作でも削除を実行しない。過去データを読む `UndoEntry.delete`、その正規化・内部key照合・復元分岐、CSVの盤外破棄判定は残す。

**配置Undoと全体リセットは別の既存操作として維持する案**とする。任意の楕円を消す削除操作の廃止から、Undoや全体リセットの全廃を推測しない。旧削除Undoを残すのは既存データの復元のためで、新しい削除履歴は作らない。

### 短いタップの移動と長押し移動を分ける

既存 `move` の上下・列制約は維持し、新しい `reposition` コマンドで長押し移動を表す。`operationId`、必須の `expectedGeneration`、現在の `id`、`expectedVersion`、必須の `expectedEntityKey`、移動先 `plate` / `x` / `y` を持つ。共有判定は `gridRepositionBlockReason(items, id, plate, cellIndex)` とし、結果を `missing | occupied | over_capacity | null` に統一する。UIのプレビューとモデルはこの同じ判定を使う。

`reposition` は最新保存状態で内部key・version・generation、移動先鉄板と空きセル、移動元・移動先の容量を検証する。同一鉄板の場合は対象自身を占有検査から除外し、鉄板間の場合は移動先にいる別の楕円との重複を拒否する。移動元または移動先が6枚を超える旧過密状態なら新しい長押し移動を拒否し、旧座標を保持する。移動後も移動元・移動先が6枚以下であることを確認する。元の鉄板・元セルへの移動は版数・履歴を増やさず無変更にする。成功時は同じ楕円のplate・位置・versionを原子的に更新し、後述の移動イベント時刻以外はID・archiveId・作成順・生地残数・加熱開始時刻・温度区間・完成期限を維持する。遅延したID操作で別の楕円を動かさないよう内部keyを必ず照合する。

長押し中は移動先の鉄板・マスと可否を表示する。pointer captureは押下元SVGに保持しつつ、各pointer move / upのclient座標を**両SVGの矩形**と照合して移動先の鉄板を求める。キャプチャ中のevent.currentTargetを移動先だと扱わない。両方の矩形外なら候補なしとし、隙間や盤外を端のセルへ無条件に丸めない。pointer up時に描画範囲と最新占有を再確認してから一度だけ送信する。450ms前に12 CSS px以上動いた操作は長押しとして成立させず、通常タップも発火させない。450ms到達後のドラッグはタップと排他的に扱う。pointer cancel / lost capture、世代変更、対象更新、保存停止・復元中、画面破棄では予告を消してキャンセルする。

ドロップ候補の座標はSVG外接矩形に対する単純な比率で求めない。PCの正方形plateには `viewBox="0 0 1600 900"` の描画範囲外の余白が生じるため、矩形内でも余白を有効なセルとして扱うと移動先がずれる。矩形内にある候補SVGの `getScreenCTM()` を取得し、その逆行列でclient座標をviewBox座標へ変換する。変換後の `x` が0〜1600、`y` が0〜900の範囲内の場合だけ `gridCellAt(x / 1600, y / 900)` でセルを選ぶ。行列が取得できない・逆変換できない・座標が不正、または描画範囲外なら候補なしとしてキャンセルする。縦横比16:9のPagesも同じ手順を使い、プレビューとpointer upで判定を統一する。

### 移動記録とUndo

CSVの列名を維持し、`movedToUpperAt` は**最新の成功した下段→上段移動の時刻**とする。長押し移動では移動前と移動後の行を比較し、鉄板・列が同じか異なるかを問わず、下段→上段の成功時だけ更新する。例として鉄板1の下段から鉄板2の上段へ移すと更新し、鉄板1の下段から鉄板2の下段、鉄板1の上段から鉄板2の上段・下段へ移す場合は既存値を保持する。現在位置が下段に戻っても過去の下段→上段イベント時刻は残す。既存の同列短いタップの `move` でも従来どおり更新する。全移動の履歴や移動元・先の鉄板列をCSVへ追加することは今回の範囲に含めない。

新規の `move` と `reposition` のUndoに、移動前の `movedToUpperAt` を保存する任意フィールド（例：`previousMovedToUpperAt?: number | null`）を追加する。既存の `from.plate` / `from.x` / `from.y` で元の鉄板・セルを保持し、Undoは元鉄板の占有・容量を再確認してからplate・位置・元時刻をまとめて復元する。元マスに別の楕円がある場合は副作用なしで拒否する。旧履歴で時刻フィールドがない場合だけ、現在の互換動作どおりnullへ戻す。新フィールドは正規化時にnullまたは有効な時刻であることを検証・保持する。

UndoEntryは既存の `type:"move"` を利用し、保存schema12とバックアップformatVersion 1は維持する案とする。新メタデータは追加の任意フィールドで後方互換を保つ。旧削除Undoと過密復元情報は消さず、新しい通常移動制限を旧Undo復元に適用しない。不要な過去データ移行・全体初期化は行わない。

## IDの一致についての制約

**削除機能を廃止しても、画面IDとCSV記録IDの一致は保証されない。** 現在の `relabelEntities` は鉄板上と内部完成品を作成順に `1-1` から詰め直す一方、`archiveId` / 実行記録IDは保存済みの安定した識別子である。

- 完成品の提供・取り出し `remove` 後に画面IDが詰め直される。新規削除がなくてもこの経路は残る。
- 配置Undoは画面集合から楕円を除き、内部採番と生地消費を戻す既存操作である。
- 生地タイマーの初回開始時の24個境界への丸め、期限切れセットの未使用番号スキップでは記録IDの高水位が進む。画面の連続番号は同じ空き番号を表さない。
- 旧データの移行や記録ID衝突回避でUUID形式のarchiveIdを持つ楕円・記録が存在しうる。

ID改善はユーザーの別途判断が必要であり、今回の削除廃止・長押し移動には、ID統合・再採番停止・過去記録の書き換えを含めない。実装説明でも「削除廃止によりIDが必ず一致する」とは案内しない。

## 検証方法と受け入れ条件

計画作成時点ではコード変更・テストを行わなかった。現在の実装依頼では、typecheck、lint、Pages / PCビルド、`git diff --check` とブラウザーまたは実機での操作確認を行い、実際に実施した内容だけ報告する。テスト追加は行わない。自動操作で長押しドラッグを完遂できなければ、その操作は未確認と明記する。push後はGitHub Pagesの公開更新を確認し、反映状況を記録する。

- 白・黒・赤を、同一鉄板および鉄板1→2／2→1の任意の空きセルへ長押し移動できる。上下・左右・斜め・異なる列を含め、両鉄板各6マスを候補にする。
- 使用中のマス、両鉄板外・鉄板間の隙間、元鉄板の元マス、移動元または先の過密状態では位置を変えず、削除・記録作成・タイマー開始・回収を起こさない。旧過密データの位置を保持する。
- pointer captureが元SVGにある状態でも移動先SVGをclient座標で選択できる。縦並び・横並びで両方向の鉄板間移動を確認し、離す直前に使用中となったマスへの保存は拒否する。鉄板間移動の成功時は元鉄板の枚数が1減り、移動先が1増えて6枚以下に収まる。
- PCの正方形plateとPagesの16:9表示の両方で、見えているセルとドロップ候補が一致する。SVGの外接矩形内でもviewBox描画範囲外の余白では候補を表示せず、離しても移動しない。
- 赤の短いタップは回収、長押しは位置移動だけ。白・黒の短いタップと温度矢印・新規配置も現在の規則を維持する。
- 長押し成立前のスワイプ、指を元位置へ戻す操作、長押しして動かさず離す操作、pointer cancel / lost captureで誤タップや保存が発生しない。縦横画面・小画面で候補マスと案内を確認できる。
- UIと直接コマンドの両方で新規deleteが拒否される。古い・異なる内部key、version、generationのrepositionは副作用なしで拒否される。
- 成功した移動は90秒の起点・温度区間・30分期限・生地残数・各識別子を保つ。鉄板間を含めて下段→上段の時刻だけを更新し、同段・上段→下段では以前の値を保つ。
- 複数の同一・別鉄板移動とUndoで、元鉄板・元位置・直前の移動時刻を正しく復元する。戻り先の占有・容量変更時は誤復元を拒否する。旧move / delete履歴、盤外破棄記録、過密保存、JSONバックアップを失わず読み込める。
- 再読込・画面復帰・JSONバックアップ往復で新位置とUndo時刻を保持する。ID再採番方式、提供状況のID照会、完成品記録の既存仕様を変更しない。

## 確定事項と計画の自己確認

移動範囲はユーザー回答により**両鉄板の各6マスの空きマスへ移動**する仕様に確定した。確認待ちは解除した。白・黒・赤を対象にすること、450ms維持、配置Undo・全体リセット・旧削除Undoの互換維持は、既存機能を保つ設計として維持する。

調査で削除・短いタップ・モデル・保存・Undo・イベント時刻・採番の経路を確認した。通常moveの制約を誤って拡張せず、長押し用repositionだけに鉄板間移動を許可する。源／先の占有・容量と、元鉄板を含むUndo復元を同じ契約に整理した。新規削除だけを止めて旧データを読む構成とし、ID一致の改善は範囲外である。計画を停止する未決事項はない。現在の依頼範囲は本計画に沿う実装・検証と、完了後のpush・公開更新である。
