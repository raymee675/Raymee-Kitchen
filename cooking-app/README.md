# 鉄板タイマー（GitHub Pages版）

現在の利用・サポート対象は、固定したスマートフォン1台の同じブラウザー保存領域で使うGitHub Pages版です。ログイン、端末登録、複数端末間の共有はありません。運用上の詳細は[現行構成の正本](../docs/single-phone-github-pages-architecture.md)、文書一覧は[docs索引](../docs/README.md)を参照してください。

## 利用を始める

2026-10-09の公開記録では、次のURLに対するActions run 13が成功し、HTML・更新後のJavaScript・CSSがHTTP 200を返しています：[https://raymee675.github.io/Raymee-Kitchen/](https://raymee675.github.io/Raymee-Kitchen/)。固定スマートフォンでの実操作は未確認です。2026-10-03に報告されたWeb Locks APIの実行時エラーに対する修正はmainへ反映されていますが、固定端末での運用受け入れは確認されていません。公開状況の詳細は[現行構成の正本](../docs/single-phone-github-pages-architecture.md)を参照してください。

利用する場合は、スマートフォンをインターネットへ接続してページを開きます。ホーム画面に追加して使う場合は、最初に決めた起動方法を続けて使ってください。通常タブとホーム画面からの起動で保存領域が異なることがあるため、途中で切り替えないでください。

鉄板は2枚あり、それぞれ6マスです。スマートフォンの縦画面では2枚を縦並び、横画面では横並びに同じ画面へ表示します。下段の空きマスをタップすると待機中の楕円を配置できます。同じ列の上段が空いていれば、下段の待機中楕円をタップした最初の操作で上段へ移動し、上段でタップすると固定90秒の加熱を開始します。上段が埋まっている場合は下段の待機中楕円をタップすると計測が始まります。焼き上がった楕円はタップして回収し、内部で30分の提供タイマーを開始します。必要な完成品をID指定で完成ボックスに呼び出し、画面上部から完了記録のCSVを書き出せます。新規配置は空きマスとID上限の制約を受けます。

楕円本体を450ミリ秒以上長押ししてからドラッグすると、同じ鉄板でも別の鉄板でも、空いているマスへ移動できます。白・調理中・焼き上がりのどの状態も移動でき、計測開始時刻・温度設定・生地残数・IDは移動によって変わりません。使用中のマス、鉄板間の隙間、鉄板外で離すと元の場所に戻ります。長押し移動では計測開始や回収を行いません。移動は画面上部の**操作を取り消す**で、元の鉄板・マス・移動前の記録時刻へ戻せます。

お好み焼きを個別に削除する機能はありません。配置の取り消しと全体リセットは維持します。画面左上の戻る矢印が「直前の操作を取り消す」です。操作方法・保存条件・例外の説明は、ヘルプボタンから開くマニュアルに集約しています。通常画面には説明文や成功通知を表示しません。

## 横画面の配置

上部左に戻る矢印とデータ操作・マニュアルのアイコン、その下に生地の残数と残り時間を表示します。右隣が小型のID呼び出し、その右から画面右端までが完成ボックスです。下部には2枚の鉄板を横並びに表示し、横画面の通常操作ではページをスクロールさせません。マニュアルとデータ管理は必要時に開き、内部をスクロールできます。

## 提供状況とID

鉄板・完成ボックス・CSVでは、配置時に割り当てられた固定IDを使います。提供やUndoで他のお好み焼きのIDが変わることはありません。内部操作用の識別子は表示しません。既存の保存記録・CSVのIDは書き換えません。旧データや衝突回避によりUUID形式のIDが残る場合は、CSV・JSON内に保持されますが、数値のm/n呼び出しの対象外です。

赤い楕円の回収から30分間が提供期限です。上段の左右ボタンでm（1〜8）、下段でn（1〜24）を選び、中央のIDをタップすると完成ボックスに呼び出します。新しく呼び出したIDを上に最大5件まで縦に表示し、6件目からは最も古い表示を外します。同じIDの再呼び出しは先頭へ移動し、重複しません。表示から外れても完成品・記録は保持します。呼び出し一覧は再読込時に空になります。矢印だけでは照会を変更せず、照会しても期限は延長されません。

完成ボックスには指定IDと「提供可能／提供不可能／提供済み／未準備」を表示します。提供可能な場合は元の期限までの残り時間（分:秒）と「提供」ボタンを表示します。「提供」を押すと提供済みとして保存します。期限切れ・提供済み・未準備には提供ボタンを表示しません。確定処理時点で期限が切れていた場合は、提供不可能として扱います。

## 生地タイマー

生地の欄には未使用の残数 `n/6` と残り時間だけを表示します。未開始の欄をタップすると、冷蔵庫から取り出した6個分の20分タイマーを開始します。新しい楕円の配置が保存されたときだけ残数が減り、加熱開始・移動・回収では減りません。計測中は欄をタップしてもリセットされません。

20分を過ぎたら残りを廃棄し、欄をタップして次の6個分を開始してください。6個を使い切った後も同じ欄から次の6個分を開始できます。24個のID区間を6個ずつ4回で使います。開始時にID区間の途中なら未使用IDを飛ばします。期限切れの残りIDは再利用せず、最終ID `8-24` の後は周回しません。生地の状態はJSONバックアップに含まれます。

旧24個タイマーが未完了の場合は、調理操作と復元を停止し、全体リセットの確認を表示します。

## 実行記録CSV

CSVは回収済みの実行記録を、安定した記録IDごとに1データ行で出力します。CSVの「お好み焼きID」はentityごとに保持するarchive IDで、画面と同じ固定IDです。通常は配置時に割り当てた`M-N`形式ですが、schema 10からの移行や新規作成で既存archive IDとの衝突を避ける必要がある場合、そのentityにはentityKeyから決まるUUIDを割り当てることがあります。そのentityが記録された場合、CSVにはそのUUIDが出ます。過去の盤外削除による開始済み楕円の記録IDも保持されます。列名と列数は従来どおりです。「鉄板投入時刻」は新規配置が保存された時刻、「下段→上段移動時刻」は、鉄板間も含む直近の下段から上段への移動が保存された時刻です。上段から下段や同段の移動では前の値を保持します。移動をUndoすると移動前の時刻へ戻ります。以前の保存データなど取得できない時刻は空欄です。温度区間は「温度区間(℃・開始順)」、各区間の秒数は「区間加熱秒数(開始順)」の列に ` | ` 区切りで並び、同じ位置どうしが対応します。温度不明の区間も「温度不明」として同じ位置に残ります。1区間だけの場合もリスト形式です。合計加熱秒数、タイマー開始・回収・焼き上がり・保管・提供の時刻、最終ステータス、提供不可理由は記録ごとに1回出力します。盤面に残っている楕円は含みません。

CSVの列は、お好み焼きID、鉄板投入時刻、下段→上段移動時刻、タイマー開始時刻、回収時刻、温度区間(℃・開始順)、区間加熱秒数(開始順)、合計加熱秒数、焼き上がり時刻、30分タイマー開始時刻、提供時刻、30分タイマー期限時刻、30分タイマー停止時刻、最終ステータス、提供不可理由です。Excelで開きやすいようUTF-8 BOM、CRLF、引用符付きフィールドを使います。すでに保存したCSVファイルの内容は変わりません。

## 保存、オフライン利用、更新

- 調理状態、完成ボックス、実行記録、操作取り消し履歴は、このサイトを開いたブラウザーの`localStorage`に保存します。スマートフォンを1台に固定し、同じブラウザーと起動方法を使ってください。別端末や別ブラウザーとは同期されません。
- ブラウザーのサイトデータ削除、プライベートブラウズの終了、ブラウザー変更、端末交換などで調理状態が失われることがあります。画面の**データ管理**から盤面・タイマー・完成ボックス・実行記録・次のお好み焼きIDをJSONへ手動保存し、内容を確認してから現在の保存データへ復元できます。JSONはブラウザーのダウンロード先に保存され、自動送信・自動バックアップはありません。端末外にも残す場合は別の場所へ保管してください。CSVは完了した実行記録だけの出力で、盤面の復元には使えません。
- 画面上部の**リセット**は、このサイト用に保存した調理データと生地タイマーを初期化します。以前の盤面が必要な場合は、先に保存したJSONバックアップから復元してください。Service Workerの画面キャッシュは残ります。ブラウザーのサイトデータを削除すると、調理データだけでなくオフライン用キャッシュも失われることがあります。
- 初回表示と新しい版の取得にはインターネット接続が必要です。Service Workerが必要な静的ファイルをキャッシュした後は、キャッシュが残っている場合に限りオフラインで再起動できます。キャッシュは調理データのバックアップではありません。
- 新しい版は調理中に自動適用しません。調理を終えてから画面の更新アイコンを押して切り替えてください。画面ロック中にタイマー表示が毎秒更新されることや、音・通知で知らせることは保証しません。
- GitHub Pagesのサイト自体は公開アクセス可能です。URLを開いた別の人にはその人のブラウザー内に別のデータが作られますが、同じスマートフォンや同じブラウザー保存領域を使える人は保存中の状態を見たり操作したりできます。

## Pages版の開発と公開

Node.js 24.19.0以上とnpmを用意し、依存関係とPages向けビルドは`cooking-app/`で実行します。

```powershell
cd cooking-app
npm ci
npm run typecheck
npm run build:pages
```

ビルド成果物は`cooking-app/dist-pages/`です。リポジトリルートの[Pages workflow](../.github/workflows/deploy-pages.yml)は、`main`または`master`への対象ファイルのpush、または手動実行でPages版をビルドして公開します。GitHubの **Settings > Pages > Build and deployment > Source** は **GitHub Actions** に設定します。ローカルでビルドしただけでは公開されません。

依存関係のlockfileは`cooking-app/package-lock.json`です。Pagesのベースパスは`PAGES_BASE_PATH`で指定し、Actionsではリポジトリ名から設定されます。
