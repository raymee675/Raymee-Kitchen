# 鉄板タイマー（PC版）

このプロジェクトは、Windows PCで動かす鉄板タイマー専用です。PCがサーバーとして調理状態を保存し、同じWi-FiまたはPCのモバイル ホットスポットにつないだスマートフォンから共同操作します。

## 起動要件

- Windows 10/11
- Node.js 24.19.0以上（npm付き）
- 初回準備時はパッケージのインストールと画面のビルドが必要です

通常の起動は、プロジェクトの親フォルダーにある`起動.bat`をダブルクリックし、Windowsの確認画面で許可します。管理者PowerShellが開き、サーバー実行中はそのウィンドウが表示されたままになります。PowerShellを閉じるかCtrl+Cを押すとサーバーを停止します。起動時にTCP 8780のWindowsファイアウォール規則を作り、終了時に削除します。

起動BATはPCのブラウザーで`http://localhost:8780/`を開きます。ここは管理画面です。調理画面を見るには**調理画面を開く**を押します。localhostからの調理画面はコードなしで利用できます。

## スマートフォンを登録する

1. Windowsの**設定 > ネットワークとインターネット > モバイル ホットスポット**を開き、Wi-Fi共有をオンにします。PCとスマートフォンが同じWi-Fiにつながっている場合は、ホットスポットを使わずそのWi-Fiを使えます。
2. スマートフォンをそのWi-Fiへ接続します。
3. PCの管理画面で**登録コードを発行**し、表示されたコードと登録URLをスマートフォンへ伝えます。コードはスマートフォン1台ごとに発行し、15分以内に使ってください。
4. スマートフォンで登録URLを開き、端末名とコードを入力します。登録後、そのスマートフォンは同じURLから調理画面を使えます。
5. 管理画面の**端末の状況**で、最終接続や登録期限を確認できます。紛失・利用終了したスマートフォンは**停止**してください。

登録URLは、PCのネットワークアダプターごとに表示されます。スマートフォンが接続したWi-Fiに対応するPC側のURLを使います。複数のネットワークが表示された場合は、Windowsの`ipconfig`でホットスポット側のIPv4アドレスを確認して選んでください。

localhostと管理画面はPCからのみ利用できます。スマートフォンから管理画面URLを開いても、管理情報や管理APIにはアクセスできません。管理画面は同じPCを操作できる利用者が使える設計で、Windowsユーザーごとのログイン画面はありません。

## 調理画面の操作

- 鉄板2枚はそれぞれ横3列・縦2行の6マスです。空きマスをタップすると中央に楕円を1個配置します。楕円は従来より幅と高さを15%大きくしています。スマートフォンは縦画面で鉄板が縦並び、横画面で横並びになります。
- 新しい楕円には配置順に`1-1`から`8-24`までのIDを割り当てます。行ごとに24個ずつ進みます。配置を取り消した時、そのIDが最新の連番で、同じIDを参照する楕円・完成ボックス・実行記録が残らない場合は、次の配置でその番号を再利用します。それ以外の配置取り消しや通常操作では採番カウンターを戻しません。PC版とPages版は保存領域が別なので、それぞれ独立して採番します。
- 空きマスをタップすると温度96℃の待機楕円を配置し、楕円をタップすると固定90秒の計測を開始します。同じマスには1個だけ配置できます。
- 楕円左右の矢印をタップすると、待機中・計測中の温度を1℃単位で調整できます。
- 下段の楕円本体を長押しすると、同じ鉄板・同じ列の真上にある空き上段マスへ移動できます。上段の楕円は移動できず、左右・同段・鉄板間の移動もできません。移動先が使用中の場合や鉄板の外・鉄板間の隙間で離した場合は、楕円は元の場所に戻ります。矢印を押したままにしても移動しません。
- 旧データで1枚の鉄板に7個以上ある場合は、楕円の位置を保って表示します。新しい配置と、超過している鉄板からの移動はできません。焼き上がった楕円を完成ボックスへ移すと枚数が減り、両方の鉄板が6個以下になると、残りの楕円は自動でマスへ整理されます。
- 残り時間はサーバー時刻を基準に表示し、開始から90秒で赤くなります。赤い楕円をタップすると完成ボックスへ移り、移した時点から30分の保管タイマーが始まります。
- 完成ボックスを期限前にタップすると提供済みになります。期限時刻に青い楕円の「提供不可」へ変わり、青いアイテムをタップすると表示から取り除かれます。期限は絶対時刻で保存するため、再読み込み後も状態が続きます。
- 画面上部の**操作を取り消す**から、直近50件までの楕円配置・鉄板上の移動を順番に戻せます。PC版は共有ボードの履歴を使い、Pages版はそのブラウザー内に履歴を保存します。タイマー開始、温度変更、完成ボックスへの移動、提供・提供不可の確定後は、それ以前の取り消し履歴を消去します。配置Undoでは、対象が最新の連番IDで同じIDを参照する楕円・完成ボックス・実行記録が残らない場合に限り、その番号を再利用します。移動UndoはIDを変えません。
- 画面上部の**リセット**を押し、表示される確認ボタンで確定すると、鉄板上の楕円、完成ボックス、実行記録、操作取り消し履歴を消去してID採番を`1-1`へ戻します。PC版では登録済みの全端末で共有する調理データが対象です。Pages版では現在のサイト用にこのブラウザーへ保存した調理データだけが対象です。Pagesのオフライン起動用アプリキャッシュは保持されます。初期化済みの古い画面からの操作は拒否されます。
- 実行記録は画面上部の**記録を書き出す**からExcelで開けるCSVにできます。先頭6列にはお好み焼きID、タイマー開始時刻、回収時刻、温度ごとの区間加熱秒数、合計加熱秒数を従来どおり出力し、その後に焼き上がり・保管開始・提供・期限・タイマー停止時刻、最終ステータス、提供不可理由を追加します。計測中の温度変更は区間を分け、赤くなってから完成ボックスへ移すまでの時間も最後の区間に含めます。
- 変更はSQLiteへ保存され、接続中のほかの画面へ通常約1秒間隔で同期します。未接続中は操作を止め、接続復帰後に状態を取り直します。

スマートフォンのブラウザーで使います。画面ロック中の通知や音はありません。PCがスリープすると接続が止まるため、利用中はスリープさせないでください。

## データと復旧

調理状態、完成ボックス、回収済み実行記録、端末情報は`data-pc/kitchen.sqlite`へ保存します。実行記録はお好み焼きごとに温度区間と提供状態を保持し、CSVは開始・回収・提供関連時刻をエクスポート端末のローカル時刻で出力します。開始済みの旧データは温度変更履歴がないため、移行前の区間を「温度不明」として扱います。完成ボックス導入前の旧記録は提供状態を「導入前・判定不可」として出力します。管理画面から作る登録コードはハッシュだけをDBに保存し、コード本体は発行時に一度だけ表示します。端末セッションは登録から30日間有効です。

旧UUID形式のライブ楕円は、移行時に鉄板上の配列順、続いて完成ボックスの配列順で`M-N`へ振り直します。この順番は旧配置履歴を復元したものではありません。完了済みの過去記録は元のIDを維持します。

コマンドライン管理は補助手段として残しています。プロジェクトフォルダーで実行します。

~~~powershell
npm run device:pc -- add
npm run device:pc -- list
npm run device:pc -- revoke 端末ID
npm run device:pc -- backup
npm run restore:pc -- backups/kitchen-YYYY-MM-DD.sqlite
~~~

復元するときは、先にPCサーバーを停止してください。復元スクリプトは現在のDBを`.before-restore-...sqlite`として保存してから、整合性検査済みのバックアップに置き換えます。`data-pc/`と`backups/`はGitに含まれません。PC故障に備えて、バックアップをPC外にも保管してください。

## 開発・検証

~~~powershell
npm ci
npm run build:pc
npm run start:pc
~~~

開発サーバーは`npm run dev:pc`、モデル単体テストは`npm test`、PC APIの一時DBを使う統合確認は`npm run test:api`、型確認は`npm run typecheck`、静的解析は`npm run lint`です。APIの統合確認はテスト用一時DBで実行し、`data-pc/kitchen.sqlite`は使用しません。

## 以前のOpenAI Sites公開版について

Site版のソース、認証、ビルド設定、Cloudflare/D1依存はこのプロジェクトから取り除いています。Site版とPC版のデータは別々で、自動移行しません。以前公開したSiteのURLや保存データはこのPCアプリから管理されません。

## GitHub Pages版（固定スマートフォン1台）

`npm run build:pages`でGitHub Pages用の静的アプリを作成します。Pages版は`dist-pages/`だけを公開し、PC版のNode.jsサーバー、SQLite、端末管理画面を成果物に含めません。GitHub Actionsの公開設定はリポジトリルートの`.github/workflows/deploy-pages.yml`にあります。GitHubの **Settings > Pages > Build and deployment > Source** を **GitHub Actions** に設定してください。

Pages版の調理状態、完成ボックス、回収済み実行記録は、開いたブラウザーの`localStorage`に保存します。1台・1ブラウザーで使い、同じサイトを別タブで開いたときは同時編集を止めます。初回アクセス後にService Workerが画面一式をキャッシュすると、通信がない場所でも再起動できます。新しい版は調理中に自動適用せず、画面の更新ボタンから切り替えます。

**リセット**は現在のサイト専用の調理データ保存キーだけを初期状態へ置き換えます。Service Workerの画面キャッシュは消さないため、保存済みの画面でオフライン起動できます。

`PAGES_BASE_PATH`でリポジトリのURLパスを指定できます。GitHub Actionsではリポジトリ名から設定します。ローカルでビルドする場合の既定URLは`/`です。

Pages版はPC版と調理状態・実行記録を共有しません。ブラウザーのサイトデータ削除、別ブラウザーへの変更、端末交換に備えた自動バックアップはありません。記録を残すにはCSVを書き出して保管してください。画面ロック中の通知やアラームもありません。
